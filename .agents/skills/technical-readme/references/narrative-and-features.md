# 叙事与 Feature 选择

## 提炼技术主张

一句话定位包含项目类别及最重要的技术特征；紧接一段说明核心建模能力、计算路径与主要应用任务。首屏以项目为中心，宏观背景仅在能直接解释技术问题时引入。

## 筛选与排序

按五个方面判断 Feature 是否值得占据首页篇幅：任务价值、技术辨识度、证据成熟度、可解释性、探索入口。同一问题的不同机制可合并；有独立问题和证据的能力可拆分；基础 API、文件格式和平台支持进上手与兼容性部分。排序围绕技术链路（如几何表示 → 物理求解 → 系统规模 → 观测反馈），或从最有解释力的场景引入。

## Feature 的写作单元

每节围绕一个主要技术主张："标题 → 一段精简描述 → 媒体 → 链接"。

- 描述 1–3 句，交代能力与关键机制；案例选最有解释力的一项，将问题、方法与结果合并表达。
- 图像能直接表达的动作由图注或链接标签说明，正文不复述画面。
- 详细算法、完整参数与次要实验进入文档或报告，通过链接提供。
- 先尝试压缩为一段；新增句子须提供新的技术信息或必要条件。

示例——推荐："系统跟踪输入数据的变更，在受影响的算子之间传播增量更新，复用已有中间状态以维护查询结果。"需要修改："不只是执行查询，而是让数据焕发生命。"（以修辞和否定代替技术机制。）

## 证据的组织方式

- **实现与 API**：说明输入、输出与工作流。
- **定性演示**：说明对象、动作与观察到的现象。
- **定量评测**：给出指标、基线、关键条件与统计口径；例如"在指定模型、硬件和环境数下达到某吞吐"比结论后追加泛化免责声明更清楚。
- **端到端结果 / 真实系统对照**：明确任务与系统组成；误差结论由对应测量给出。

## 删除测试

逐句询问：这句话增加了哪项技术认识、结果判断或操作指引？给不出具体答案就删除。

| 待检查内容 | 处理方式 |
| --- | --- |
| "动态预览为 5 秒片段"、"图片经过缩放和压缩" | 删除或放入媒体处理记录 |
| "点击图片可查看完整视频"、"下文将从多个维度介绍" | 删除；入口和目录已表达相同信息 |
| "运动过程以 0.5 倍速度播放" | 影响现象解释时保留 |
| "命令在仓库根目录执行" | 保留 |
| "吞吐在指定设备与批量规模下测量" | 保留并给出具体配置 |

这些是判断示例，不是关键词黑名单。

## 语言编辑检查

- 用"表示、求解、输出、耦合、测量"等动词替代抽象价值口号；用具体配置、现象或指标替代"领先、卓越、极致"。
- 将"想试试……？"改为直接的示例或安装入口；反复的"不仅……而且……"改为直接列明机制关系。
- 删除写给作者的安排、素材搬运说明和编辑提醒；Feature 说明、图注和快速开始各承担不同信息，避免重复。
