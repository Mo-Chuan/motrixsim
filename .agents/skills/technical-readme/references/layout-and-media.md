# 排版与媒体

## 标题与目录

- 单一 H1 标识项目，H2 划分主要章节，H3 组织 Feature 或上手子项。
- 目录采用纵向 Markdown 列表，嵌套关键子项，顺序与正文一致。
- 文档、在线体验、包下载等少量外部入口可置于首屏一行。
- 为重要跳转提供稳定锚点；检查目标平台对标题 slug 和自定义 HTML 锚点的处理。

## 布局选择

### 纵向 Feature 小节

适合需要解释机制、素材数量不同或媒体宽高比差异大的内容。标题、段落、媒体与深入入口顺序稳定。单个 Demo 按内容选宽度；多 Demo 并排时用可在目标平台渲染的简单标记，并检查窄屏效果。

### 表格

适用于支持平台、指标比较、示例索引和同构能力矩阵。控制列数与单元格文本量，避免大幅媒体与长段落挤入多列表格。

Feature 表格的单元格文本以一到两句为限；启动参数、附加依赖等使用细节放到专属行、脚注或表格下方。缩略图统一尺寸；某行缺少合适素材时保留空单元格，不放不对应或不完整的内容。

### 折叠说明

适用于平台特例、可选镜像和读者需要的实验参数。核心结论及解释结论必需的条件保持可见。折叠区前后保留空行，并检查 Markdown 在 HTML 区块内的解析结果。

## 媒体选择

- 运动、交互与控制过程用视频或动态预览；材质、光照、结构和定量关系用真实截图、示意图或图表。
- 同一演示在内联动态预览与完整视频之间通常选一套维护。双格式意味着双份媒体与同步成本，只有读者确实需要完整时长版本且托管稳定时才两者都放。
- 截图与所宣传示例逐张目检比对内容，不依赖文件名判断；来源不明或展示其他内容的图片不放进入口位置。
- 图注描述对象、动作、现象、指标和必要设置；为图片添加有意义的替代文本。
- GitHub/GitLab 的内嵌视频、HTML 清理与 LFS 行为存在差异。布局优先用 Markdown 和少量 HTML，以实际托管页面验证播放与链接。

## 预览制作与资源管理

生成前检查：源文件真实性、时长分辨率、资产使用条件、LFS 规则与远端大小限制。选择包含完整可解释动作的片段，而非机械截取前几秒；按展示尺寸配置分辨率、帧率、色彩与编码，保持画面比例。

影响理解的处理（慢放、加速、放大等）在图注或素材说明中记录。保留可重复执行的生成入口，脚本参数与素材说明同步更新。

## 验证层级

1. **源文件**：链接目标存在、锚点唯一、媒体可解码、体积与属性合规。
2. **Markdown 渲染**：标题、目录、表格列数、折叠区与图片链接结构。
3. **实际页面**：桌面与窄屏可读性、媒体加载、跳转与播放。
4. **运行路径**：依赖、资源、平台启动方式、命令与预期输出。

各层独立验证，成本与修改范围匹配；交付时如实说明完成的层级。
