# 用户文档写作

帮助读者以尽可能少的前置知识完成一个明确任务，并理解关键操作及其结果。

## 核心原则

- **围绕读者目标组织。** 按“用户要完成什么”安排内容，不照搬实现结构或罗列功能。
- **按能力组织，不按后端重复。** CPU 和 GPU 共有的概念与能力在同一章节讲解，不拆成两套指南；后端之间的用法、数据类型、支持范围或性能差异，在该能力章节内用小节、标签页或对照表说明。
- **功能页标注后端支持情况。** 编写功能文档时，评估该功能在 CPU 和 GPU 版本上的支持程度（完全支持、部分支持、不支持），并在页面顶部加对应标签；标注依据应为现有文档、示例或实测证据，不臆造支持状态。后端差异的详细说明放在对应功能章节内，不集中维护单独的对比页。渲染器相关功能（渲染器、相机、Widget 等）在两个版本上通用，不加标签。
- **以当前目标版本为准，无需前向兼容。** 不为旧目录、旧链接或旧用法保留兼容页、重定向或重复说明；调整结构时直接更新当前文档中的相关链接，确保当前阅读路径完整。
- **由简入难。** 先走通一条最小成功路径，再逐步增加概念、选项和复杂度；每一步尽量只引入一个新知识点。
- **先操作，再适度解释。** 在读者需要时介绍概念，解释关键操作的原因，不在开头堆积背景，也不逐行翻译代码。
- **明确而可验证。** 写清前置条件、执行位置、输入和预期结果；不让读者猜测被省略的步骤。
- **精简但不跳步。** 使用短句、具体动词和一致术语；删去宣传语、重复说明和与当前目标无关的细节。
- **禁止防御性叙述。** 不预设读者会误解，再用“不需要先……”“不会自动……”“不等于……”“并非……”等句式逐一排除假想错误。直接说明应做的操作、实际行为和预期结果，让主流程连贯推进；已由步骤、表格或示例表达的信息不再重复辩解。影响操作正确性或安全性的必要限制，应在相关位置用简短、具体的条件说明。
- **以证据为准。** 从现有实现、参考资料和实际验证中确认行为；不编造命令、接口或运行结果，不确定的事实明确标出。

## 工作流程

### 1. 确定范围

阅读相关资料与已有文档，明确：目标读者、已有知识、一个可观察的完成目标。用户未要求改变的内容和项目约定应保留。

区分页面用途：
- **入门教程**：引导初学者完成一个完整练习，优先提供推荐路径。
- **操作指南**：帮助已有基础的读者解决一个具体问题。
- **概念说明**：解释机制、关系与取舍；无需强行写成步骤。

接口的完整定义链接到参考手册，不在用户文档中重复维护。

### 2. 确定目录分类与阅读顺序

- **先整体，后局部。** 先评审一级分类的目的与边界，再评审二级目录和文章归属，最后修改正文；局部任务无需重构整个目录。
- **先读内容，再定归属。** 根据文章的主要读者、核心问题和完成目标分类，不只凭标题或现有文件路径判断。
- **同级分类有一致主轴。** 优先围绕用户任务或知识领域组织，避免将学习阶段、功能领域、平台和内容形式随意并列；必要的例外应有清晰边界。
- **一篇文章有一个主要归属。** 跨主题内容通过交叉链接提供其他入口，不复制正文；若文章承担多个独立目标，考虑拆分。
- **按依赖安排顺序。** 从准备、基础概念和最小实践，逐步进入组合任务与进阶内容；目录名称应让读者能预测内容，避免“其他”“主要功能”等宽泛分类。
- **分类由内容支撑。** 不为对称或完整而创建空栏目；提出调整时，给出简短的目录树、分类边界和现有文章的归属理由。

验证分类时，用代表性用户问题检查“能否直观找到入口、是否存在多个难以区分的归属、是否缺少前置阅读”。导航调整与物理文件迁移分开考虑；迁移时更新当前文档中的链接、锚点和导航引用，无需保留旧入口。

### 3. 设计最小路径

从目标结果倒推必要步骤。先给出能成功的最小方案，将可选配置、替代方案和原理细节放在主流程之后。

检查依赖顺序：每一步用到的概念、文件、变量或资源，都应已被介绍、创建，或明确说明来源。

### 4. 编写逐步说明

操作型页面优先采用以下结构，按需取舍，不机械套用：

1. **目标**：说明读者将完成什么。
2. **准备**：只列本任务必需的环境、材料和前置知识。
3. **操作**：按执行顺序编号，每一步用动词说明一个明确动作。
4. **验证**：给出预期输出、可见变化或检查方法。
5. **下一步**：提供少量进阶入口；必要时补充常见问题与限制。

编写步骤时：
- 给出可复制的命令或代码，并说明执行位置；占位符必须解释。
- 完整示例应可独立运行；代码片段应说明插入位置及依赖上下文。
- 在关键节点就地说明预期结果，让读者尽早发现偏差。
- 对常见失败，按“症状 → 检查方法 → 处理方式”说明。
- 图像和视频用于辅助理解，不替代完成任务所必需的文字步骤。
- 截图入库前先压缩：按页面展示尺寸设定分辨率（通常不超过 1600px 宽），优先 JPEG/WEBP，单张控制在几百 KB 内；用截图工具的原始输出对比压缩前后，确认内容仍清晰可辨。

### 5. 验证与交付

教程包含代码时，必须实际运行代码，并将真实运行结果的截图插入教程对应步骤。图形程序截取实际界面或渲染结果，命令行程序截取有代表性的终端输出；图注说明读者应观察的结果。截图应与所展示的代码及参数一致，不使用示意图或其他示例的画面代替运行证据。环境限制导致无法运行或截图时，明确报告阻碍，不宣称已验证。

按初次阅读的顺序走查，不依赖作者才知道的隐含信息：

- 能否明确说出本页目标，读者是否知道从哪里开始？
- 步骤是否连续，术语是否先解释后使用，可选步骤是否明确？
- 示例、链接和资源是否有效，结果是否有判断标准？
- 是否重复参考手册，或混入不影响当前任务的细节？
- 是否存在为排除假想误解而添加的防御性描述？能否删除，或改为直接的操作与行为说明？
- 功能页是否已标注 CPU / GPU 支持情况？标签是否与页面内容（含后端差异说明）一致？

遵循项目现有的构建与预览流程，按改动范围验证。交付时区分已实际验证的内容与尚未验证的内容，不将构建成功等同于操作正确。
